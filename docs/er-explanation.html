3.6 แผนภาพความสัมพันธ์ของข้อมูล (Entity-Relationship Diagram)

แผนภาพความสัมพันธ์ของข้อมูล (Entity-Relationship Diagram หรือ ER Diagram) คือแบบจำลองที่แสดงโครงสร้างของฐานข้อมูลในรูปแบบกราฟิก โดยระบุตารางข้อมูล (Entity) คุณสมบัติ (Attribute) และความสัมพันธ์ระหว่างตาราง (Relationship) เพื่อให้เข้าใจการไหลของข้อมูลภายในระบบได้อย่างชัดเจน

ระบบบริหารจัดการห้องปฏิบัติการคอมพิวเตอร์ อาคาร 75 ปี วไลยอลงกรณ์ มีฐานข้อมูลที่ประกอบด้วยตารางหลัก 11 ตาราง ได้แก่ User (ผู้ใช้งาน), Room (ห้องปฏิบัติการ), Key (กุญแจ), Course (รายวิชา), Term (ภาคการศึกษา), Section (กลุ่มเรียน), Enrollment (การลงทะเบียน), Reservation (การจองห้อง), ReservationParticipant (ผู้เข้าร่วมการจอง), Loan (การยืมกุญแจ) และ KioskToken (โทเคนอุปกรณ์ Kiosk) โดยมีความสัมพันธ์ระหว่างตาราง ดังแสดงในรูปที่ 3.32

ความสัมพันธ์ระหว่างตาราง

ระบบมีความสัมพันธ์ระหว่างตารางทั้งหมด 3 รูปแบบ ได้แก่ ความสัมพันธ์แบบ หนึ่งต่อหนึ่ง (One-to-One หรือ 1:1) ความสัมพันธ์แบบ หนึ่งต่อกลุ่ม (One-to-Many หรือ 1:N) และความสัมพันธ์แบบ กลุ่มต่อกลุ่ม (Many-to-Many หรือ N:M) โดยมีรายละเอียดดังตารางต่อไปนี้

ตารางต้น ความสัมพันธ์ ตารางปลาย คำอธิบาย
Room 1:N Key ห้องปฏิบัติการ 1 ห้อง มีกุญแจได้หลายดอก (Key.roomId → Room.id)
Room 1:N Section ห้องปฏิบัติการ 1 ห้อง ถูกกำหนดใช้ในหลายกลุ่มเรียนได้ (Section.roomId → Room.id)
Room 1:N Reservation ห้องปฏิบัติการ 1 ห้อง มีรายการจองได้หลายรายการ (Reservation.roomId → Room.id)
Course 1:N Section รายวิชา 1 วิชา เปิดสอนได้หลายกลุ่มเรียน (Section.courseId → Course.id)
Term 1:N Section ภาคการศึกษา 1 ภาค มีหลายกลุ่มเรียน (Section.termId → Term.id)
User (อาจารย์) 1:N Section อาจารย์ 1 คน สอนได้หลายกลุ่มเรียน (Section.teacherId → User.id)
User (นักศึกษา) N:M Section นักศึกษา 1 คน ลงทะเบียนได้หลายกลุ่มเรียน และกลุ่มเรียน 1 กลุ่ม มีนักศึกษาหลายคน ผ่านตาราง Enrollment (Enrollment.studentId → User.id, Enrollment.sectionId → Section.id)
Section 1:N Reservation กลุ่มเรียน 1 กลุ่ม สร้างการจองแบบ IN_CLASS ได้หลายรายการตามวันเรียน (Reservation.sectionId → Section.id)
User (ผู้จอง) 1:N Reservation ผู้ใช้งาน 1 คน ส่งคำขอจองได้หลายครั้ง (Reservation.requesterId → User.id)
User (อาจารย์/แอดมิน) 1:N Reservation อาจารย์หรือแอดมิน 1 คน อนุมัติหรือปฏิเสธการจองได้หลายรายการ (Reservation.approverId → User.id)
Reservation 1:N ReservationParticipant การจอง AD_HOC 1 รายการ มีผู้เข้าร่วมได้สูงสุด 4 คน (ReservationParticipant.reservationId → Reservation.id)
User N:M Reservation ผู้ใช้ 1 คน เป็นผู้เข้าร่วมในหลายการจองได้ และการจอง 1 รายการ มีผู้เข้าร่วมหลายคน ผ่านตาราง ReservationParticipant
Reservation 1:1 Loan การจอง 1 รายการ มีบันทึกการยืมกุญแจได้ 1 รายการ (Loan.reservationId → Reservation.id แบบ Unique)
Key 1:N Loan กุญแจ 1 ดอก มีประวัติการยืมได้หลายครั้งในต่างช่วงเวลา (Loan.keyId → Key.id)
User (ผู้ยืม) 1:N Loan ผู้ใช้ 1 คน ยืมกุญแจได้หลายครั้ง (Loan.borrowerId → User.id)
User (ผู้คืน) 1:N Loan ผู้ใช้ 1 คน คืนกุญแจได้หลายครั้ง (Loan.returnedById → User.id)
User (เจ้าหน้าที่) 1:N Loan เจ้าหน้าที่ 1 คน ดำเนินการยืม/คืนกุญแจได้หลายรายการ (Loan.handledById → User.id)
KioskToken — — ตารางอิสระไม่มีความสัมพันธ์กับตารางอื่น ใช้เก็บโทเคนของอุปกรณ์ Kiosk แต่ละเครื่องที่ผ่านการจับคู่กับระบบแล้ว
คำอธิบายกระแสข้อมูลหลักของระบบ

กระแสข้อมูลหลักของระบบสามารถแบ่งออกได้เป็น 3 กระบวนการสำคัญ ดังนี้

1) กระบวนการจองห้องปฏิบัติการ

เมื่อผู้ใช้งาน (User) ส่งคำขอจองห้อง ระบบจะสร้างระเบียนใหม่ในตาราง Reservation โดยบันทึก requesterId อ้างอิงไปยัง User ผู้จอง, roomId อ้างอิงไปยังห้อง (Room) ที่ต้องการ และในกรณีที่เป็นการจองนอกตาราง (AD_HOC) ยังสามารถเพิ่มผู้เข้าร่วมในตาราง ReservationParticipant ได้สูงสุด 4 คน สำหรับการจองประเภท AD_HOC ของนักศึกษาจะอยู่ในสถานะ PENDING รอให้อาจารย์ที่ระบุใน approverId ทำการอนุมัติหรือปฏิเสธ ส่วนการจองของอาจารย์และแอดมินจะได้รับการอนุมัติโดยอัตโนมัติ

2) กระบวนการยืม-คืนกุญแจ

เมื่อการจองได้รับการอนุมัติ (สถานะ APPROVED) ผู้ใช้สามารถแสดง QR Token ที่เจ้าหน้าที่หรืออุปกรณ์ Kiosk เพื่อยืมกุญแจ ระบบจะสร้างระเบียนในตาราง Loan โดยบันทึก reservationId อ้างอิงไปยัง Reservation ที่เกี่ยวข้อง (ความสัมพันธ์แบบ 1:1) และ keyId อ้างอิงไปยัง Key ที่ถูกยืม พร้อมบันทึก checkedInAt (เวลายืม) borrowerId และ handledById เมื่อผู้ใช้คืนกุญแจ ระบบจะอัปเดต checkedOutAt และ returnedById ในตาราง Loan พร้อมเปลี่ยน status ของ Key กลับเป็น AVAILABLE และอัปเดต status ของ Reservation เป็น COMPLETED

3) กระบวนการจัดการตารางเรียน (IN_CLASS)

แอดมินสามารถนำเข้าข้อมูลรายวิชา (Course) ภาคการศึกษา (Term) และกลุ่มเรียน (Section) เข้าสู่ระบบ ตาราง Section จะเชื่อมโยงกับ Course, User (อาจารย์ผู้สอน), Room และ Term ด้วย Foreign Key นักศึกษาที่ลงทะเบียนเรียนจะมีระเบียนใน Enrollment ที่เชื่อมระหว่าง User กับ Section ระบบจะสร้างรายการ Reservation ประเภท IN_CLASS ล่วงหน้าจากข้อมูลใน Section สำหรับทุกวันที่มีการเรียนในช่วงภาคการศึกษานั้น
