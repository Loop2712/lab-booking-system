# บทที่ 2
# ทฤษฎีและเทคโนโลยีที่เกี่ยวข้อง

ในการพัฒนา **ระบบบริหารจัดการห้องปฏิบัติการคอมพิวเตอร์ อาคาร 75 ปี วไลยอลงกรณ์ ผ่านการสแกนบัตรนักศึกษา** ผู้จัดทำได้ศึกษาทฤษฎี หลักการ และเทคโนโลยีที่เกี่ยวข้องเพื่อใช้เป็นกรอบแนวคิดในการวิเคราะห์ ออกแบบ และพัฒนาระบบให้สามารถทำงานได้อย่างถูกต้อง ปลอดภัย และมีประสิทธิภาพ โดยแบ่งเนื้อหาออกเป็น 2 ส่วน ได้แก่ ทฤษฎีและงานวิจัยที่เกี่ยวข้อง และเทคโนโลยีที่เกี่ยวข้อง ดังรายละเอียดต่อไปนี้

## 2.1  ทฤษฎีและงานวิจัยที่เกี่ยวข้อง

### 2.1.1  ทฤษฎีระบบสารสนเทศเพื่อการบริหารจัดการ

ระบบสารสนเทศเพื่อการบริหารจัดการ (Management Information System: MIS) หมายถึง ระบบที่นำเทคโนโลยีคอมพิวเตอร์มาประยุกต์ใช้ในการจัดเก็บ ประมวลผล และแสดงผลข้อมูลเพื่อสนับสนุนการตัดสินใจของผู้บริหารและการดำเนินงานในระดับปฏิบัติการ องค์ประกอบสำคัญของระบบสารสนเทศประกอบด้วย (1) ข้อมูลนำเข้า (Input) ได้แก่ ข้อมูลห้อง ข้อมูลผู้ใช้งาน ตารางเรียน คำขอจองห้อง (2) การประมวลผล (Process) เช่น การตรวจสอบสิทธิ์ การตรวจสอบการชนกันของเวลาจอง การออกโทเคนยืนยันตัวตน (3) การจัดเก็บข้อมูล (Storage) ในฐานข้อมูลเชิงสัมพันธ์ และ (4) ผลลัพธ์ (Output) ได้แก่ รายงานการใช้งานห้อง สถิติการยืม-คืนกุญแจ และไฟล์รายงานในรูปแบบ PDF

ในบริบทของระบบบริหารจัดการห้องปฏิบัติการคอมพิวเตอร์ ระบบสารสนเทศช่วยทดแทนกระบวนการบันทึกด้วยมือซึ่งมีความล่าช้าและผิดพลาดสูง ให้กลายเป็นกระบวนการอัตโนมัติที่สามารถตรวจสอบและสรุปผลย้อนหลังได้อย่างเป็นระบบ สอดคล้องกับวัตถุประสงค์ของโครงงานในข้อ 1.2 ที่กำหนดให้ระบบสามารถจอง ยืม-คืน และรายงานสถิติได้อย่างถูกต้องและรวดเร็ว

### 2.1.2  ทฤษฎีการพัฒนาเว็บแอปพลิเคชัน

#### 2.1.2.1  สถาปัตยกรรมแบบ Client-Server

สถาปัตยกรรมแบบ Client-Server เป็นรูปแบบการสื่อสารระหว่างเครื่องลูกข่าย (Client) ซึ่งโดยปกติคือเว็บเบราว์เซอร์ของผู้ใช้ และเครื่องแม่ข่าย (Server) ซึ่งทำหน้าที่ประมวลผลคำขอและตอบกลับด้วยข้อมูลที่เหมาะสม การสื่อสารเกิดขึ้นผ่านโปรโตคอล HTTP/HTTPS โดยใช้รูปแบบของ RESTful API ที่กำหนดเส้นทาง (Endpoint) และวิธีการ (HTTP Method) ได้แก่ GET, POST, PATCH และ DELETE สำหรับการอ่าน เพิ่ม แก้ไข และลบข้อมูลตามลำดับ

#### 2.1.2.2  สถาปัตยกรรมแบบ 3 ชั้น (Three-Tier Architecture)

ระบบเว็บแอปพลิเคชันสมัยใหม่นิยมแยกการทำงานออกเป็น 3 ชั้น ได้แก่ (1) **ชั้นนำเสนอ (Presentation Layer)** ทำหน้าที่แสดงผลและรับข้อมูลจากผู้ใช้ผ่านส่วนติดต่อ (UI) (2) **ชั้นตรรกะทางธุรกิจ (Business Logic Layer)** ทำหน้าที่ประมวลผล ตรวจสอบกฎเกณฑ์ทางธุรกิจ และจัดการกระบวนงาน เช่น การอนุมัติคำขอจอง การออกโทเคน การเปลี่ยนสถานะการจอง และ (3) **ชั้นข้อมูล (Data Layer)** ทำหน้าที่จัดเก็บและเข้าถึงข้อมูลในฐานข้อมูลผ่านชั้นกลาง ORM การแยกชั้นเช่นนี้ช่วยให้ระบบบำรุงรักษาง่าย ขยายต่อได้ และเปลี่ยนเทคโนโลยีบางส่วนได้โดยไม่กระทบส่วนอื่น

#### 2.1.2.3  แนวคิด Server-Side Rendering (SSR) และ Server Components

การเรนเดอร์หน้าเว็บที่ฝั่งเซิร์ฟเวอร์ (SSR) คือการสร้าง HTML ที่สมบูรณ์ก่อนส่งให้เบราว์เซอร์ ซึ่งให้ประโยชน์ด้านความเร็วในการแสดงผลครั้งแรก (First Contentful Paint) และความปลอดภัยเนื่องจากตรรกะทางธุรกิจไม่ถูกเปิดเผยต่อผู้ใช้โดยตรง ในระบบที่พัฒนานี้ใช้รูปแบบ **React Server Components** ตามแนวทาง App Router ของ Next.js ที่อนุญาตให้คอมโพเนนต์เลือกได้ว่าจะทำงานที่ฝั่งเซิร์ฟเวอร์หรือฝั่งไคลเอนต์ ตามความเหมาะสมของแต่ละหน้าจอ

### 2.1.3  ทฤษฎีการยืนยันตัวตนและการควบคุมการเข้าถึง

#### 2.1.3.1  การยืนยันตัวตน (Authentication)

การยืนยันตัวตน หมายถึง กระบวนการพิสูจน์ว่าผู้ที่กำลังเข้าใช้ระบบเป็นบุคคลที่ถือสิทธิ์จริง โดยทั่วไปใช้ปัจจัยอย่างน้อยหนึ่งอย่าง ได้แก่ สิ่งที่ผู้ใช้รู้ (Something you know — รหัสผ่าน) สิ่งที่ผู้ใช้มี (Something you have — บัตรนักศึกษา/โทเคน) หรือสิ่งที่ผู้ใช้เป็น (Something you are — ลักษณะชีวมิติ) ระบบนี้ใช้รูปแบบรหัสประจำตัวนักศึกษา/อีเมล คู่กับรหัสผ่าน เป็นปัจจัยหลักในการเข้าสู่ระบบ และใช้ **QR Token** เป็นปัจจัยที่สองสำหรับการยืนยันตัวตนที่จุด Kiosk และเคาน์เตอร์ยืม-คืน

#### 2.1.3.2  JSON Web Token (JWT)

JWT เป็นมาตรฐานเปิดสำหรับการแลกเปลี่ยน Claims ระหว่างฝ่ายต่าง ๆ อย่างปลอดภัย ตามข้อกำหนด RFC 7519 โทเคนประกอบด้วย 3 ส่วน ได้แก่ Header, Payload และ Signature เชื่อมต่อกันด้วยเครื่องหมายจุด การลงนามใช้อัลกอริทึม HMAC-SHA256 หรือ RSA ทำให้ฝ่ายผู้รับสามารถตรวจสอบความสมบูรณ์ของข้อมูลโดยไม่ต้องเก็บสถานะที่ฝั่งเซิร์ฟเวอร์ ในระบบที่พัฒนานี้ใช้ JWT สำหรับเก็บเซสชันของผู้ใช้ (NextAuth JWT Strategy) ทำให้สามารถปรับขยายเซิร์ฟเวอร์แบบไร้สถานะ (Stateless) ได้

#### 2.1.3.3  การควบคุมการเข้าถึงตามบทบาท (Role-Based Access Control: RBAC)

RBAC เป็นรูปแบบการกำหนดสิทธิ์การเข้าถึงทรัพยากรในระบบโดยอิงจากบทบาท (Role) ของผู้ใช้ แทนการกำหนดสิทธิ์ระดับผู้ใช้รายบุคคล ระบบที่พัฒนานี้กำหนดบทบาทออกเป็น 3 บทบาท ได้แก่ **STUDENT** (นักศึกษา) **TEACHER** (อาจารย์) และ **ADMIN** (ผู้ดูแลระบบ) โดยแต่ละบทบาทมีขอบเขตการใช้งานที่แยกจากกันชัดเจน การตรวจสอบสิทธิ์ดำเนินการทั้งใน Layout ของหน้าจอ (Server-Side Guard) และที่ระดับ API Route ก่อนการประมวลผลคำขอใด ๆ

#### 2.1.3.4  Hashed Message Authentication Code (HMAC) สำหรับ QR Token

HMAC คือกลไกการสร้างรหัสตรวจสอบความสมบูรณ์ของข้อความโดยใช้ฟังก์ชันแฮชเข้ารหัสร่วมกับกุญแจลับ ระบบนี้ใช้ HMAC-SHA256 สร้างลายเซ็นต่อข้อมูล `{uid, exp}` (รหัสผู้ใช้และเวลาหมดอายุ) ที่เข้ารหัสแบบ Base64URL เพื่อนำมาสร้างเป็น QR Code สำหรับให้นักศึกษาแสดงต่อเครื่อง Kiosk หรือเคาน์เตอร์ยืม-คืน โทเคนจะมีอายุการใช้งานสั้นเพียง 10 นาที (TTL = 600 วินาที) เพื่อลดความเสี่ยงในการนำโทเคนไปใช้ซ้ำหากถูกบันทึกภาพไว้ การตรวจสอบความถูกต้องของลายเซ็นใช้การเปรียบเทียบแบบ Constant-Time ด้วยฟังก์ชัน `crypto.timingSafeEqual` เพื่อป้องกัน Timing Attack

### 2.1.4  ทฤษฎีฐานข้อมูลเชิงสัมพันธ์และ ORM

ฐานข้อมูลเชิงสัมพันธ์ (Relational Database) จัดเก็บข้อมูลในรูปแบบของตารางที่มีความสัมพันธ์ระหว่างกันผ่านคีย์หลัก (Primary Key) และคีย์นอก (Foreign Key) สามารถบังคับใช้กฎความสมบูรณ์ของข้อมูล (Integrity Constraints) ได้แก่ Entity Integrity, Referential Integrity และ Domain Integrity ทำให้เหมาะสมกับข้อมูลที่มีโครงสร้างชัดเจนและต้องการความถูกต้องสูง เช่น ข้อมูลการจองห้องที่ห้ามมีการจองชนกันในช่วงเวลาเดียวกัน

Object-Relational Mapping (ORM) เป็นเทคโนโลยีที่เชื่อมโยงโครงสร้างข้อมูลในฐานข้อมูลเชิงสัมพันธ์เข้ากับโครงสร้างวัตถุในภาษาโปรแกรม ทำให้นักพัฒนาสามารถเข้าถึงข้อมูลผ่านเมท็อดของออบเจ็กต์แทนการเขียนคำสั่ง SQL โดยตรง ลดความเสี่ยงจาก SQL Injection และเพิ่มความสามารถในการบำรุงรักษาโค้ด ในระบบที่พัฒนานี้ใช้ Prisma ORM ร่วมกับฐานข้อมูล PostgreSQL ซึ่งสามารถสร้างไฟล์ Schema และทำการย้ายโครงสร้าง (Migration) ได้อย่างเป็นระบบ

### 2.1.5  ทฤษฎี QR Code และการประยุกต์ใช้ในระบบยืนยันตัวตน

QR Code (Quick Response Code) เป็นบาร์โค้ดสองมิติที่พัฒนาโดยบริษัท Denso Wave ในปี ค.ศ. 1994 สามารถจัดเก็บข้อมูลตัวอักษรและตัวเลขได้มากกว่าบาร์โค้ดแบบดั้งเดิมประมาณ 100 เท่า มีกลไกแก้ไขความผิดพลาด (Error Correction) ตามมาตรฐาน Reed-Solomon ทำให้สามารถอ่านได้แม้ภาพถูกบดบังบางส่วน ในระบบยืนยันตัวตนสมัยใหม่นิยมนำ QR Code มาใช้เป็นพาหะนำส่งโทเคนที่ลงนามด้วย HMAC ทำให้ผู้ใช้สามารถยืนยันตัวตนโดยเพียงแสดงภาพในโทรศัพท์มือถือต่อเครื่องสแกน โดยไม่จำเป็นต้องใช้บัตรประจำตัวจริงหรืออุปกรณ์เพิ่มเติม ลดความเสี่ยงในการสูญหายและสับสนของบัตรประจำตัวนักศึกษา ซึ่งเป็นปัญหาหลักของระบบยืม-คืนแบบเดิมตามที่กล่าวไว้ในบทที่ 1

### 2.1.6  งานวิจัยที่เกี่ยวข้อง

#### 2.1.6.1  ระบบจองห้องประชุมออนไลน์

มีงานพัฒนาระบบจองห้องประชุมหรือห้องเรียนผ่านเว็บแอปพลิเคชันจำนวนมากในประเทศไทย เช่น ระบบจองห้องประชุมของหน่วยงานมหาวิทยาลัยและหน่วยงานราชการ ซึ่งโดยทั่วไปนำเสนอฟังก์ชันพื้นฐาน ได้แก่ การจองล่วงหน้า การยกเลิกการจอง และการดูสถานะการใช้ห้อง อย่างไรก็ตามระบบเหล่านี้มักไม่ได้รวมกระบวนการยืม-คืนกุญแจไว้ในระบบเดียวกัน ทำให้ยังคงมีกระบวนการแบบกระดาษอยู่ที่จุดยืม-คืน ระบบที่พัฒนาในโครงงานนี้แตกต่างจากระบบที่กล่าวมาตรงที่รวมกระบวนการจอง การอนุมัติ การยืมกุญแจ และการคืนกุญแจไว้ในระบบเดียวกัน พร้อมระบบ Kiosk สำหรับยืม-คืนแบบบริการตนเองด้วย QR Code

#### 2.1.6.2  การประยุกต์ใช้ QR Code เพื่อการเช็คชื่อและยืนยันตัวตนในสถาบันการศึกษา

ในช่วงสถานการณ์ของโรคติดเชื้อไวรัสโคโรนา 2019 มีการพัฒนาระบบเช็คชื่อด้วย QR Code ในสถานศึกษาอย่างแพร่หลาย โดยใช้หลักการคล้ายกับระบบที่พัฒนานี้คือออกโทเคนระยะสั้นที่ลงนามด้วยกุญแจลับ เพื่อให้ผู้ใช้แสดงต่อเครื่องสแกน ผลการศึกษาพบว่าระบบดังกล่าวลดเวลาในการเช็คชื่อได้อย่างมีนัยสำคัญและช่วยลดการสัมผัสกระดาษ/บัตร ระบบที่พัฒนานี้ขยายแนวคิดดังกล่าวมาประยุกต์ใช้กับการยืม-คืนกุญแจห้องปฏิบัติการ

#### 2.1.6.3  ระบบบริหารจัดการกุญแจอิเล็กทรอนิกส์ (Electronic Key Management System)

ในภาคอุตสาหกรรมและสำนักงานขนาดใหญ่ มีระบบบริหารจัดการกุญแจที่บันทึกเวลาเข้า-ออกของผู้ยืมแต่ละราย โดยใช้ตู้กุญแจอิเล็กทรอนิกส์ที่ปลดล็อกได้เฉพาะกุญแจที่ผู้ใช้มีสิทธิ์ ระบบเหล่านี้สามารถสร้างรายงานสถิติย้อนหลังและตรวจสอบความรับผิดชอบ (Accountability) ได้อย่างชัดเจน แม้ระบบที่พัฒนาในโครงงานนี้จะไม่ได้รวมตู้กุญแจฮาร์ดแวร์ แต่ได้นำแนวคิดการบันทึกประวัติการยืม-คืนพร้อมเวลาและผู้ดำเนินการมาประยุกต์ใช้ ทำให้สามารถตรวจสอบย้อนหลังได้ในระดับเดียวกัน

#### 2.1.6.4  การออกแบบ Single-Page Web Application ด้วย React และ Next.js

มีงานวิจัยและบทความวิชาการจำนวนมากที่ศึกษาประสิทธิภาพและข้อดี-ข้อเสียของการพัฒนาเว็บแอปพลิเคชันด้วย React และ Next.js เปรียบเทียบกับสถาปัตยกรรมแบบดั้งเดิม โดยพบว่ารูปแบบ Server-Side Rendering ของ Next.js ช่วยปรับปรุงความเร็วในการโหลดหน้าแรกและลดภาระของเครื่องผู้ใช้ ขณะเดียวกันการแยกคอมโพเนนต์ตามแนวคิด React ช่วยให้พัฒนาและบำรุงรักษาส่วนติดต่อผู้ใช้ได้สะดวก ระบบที่พัฒนาในโครงงานนี้นำแนวคิดเหล่านี้มาประยุกต์ใช้ทั้งหมด

## 2.2  เทคโนโลยีที่เกี่ยวข้อง

### 2.2.1  ภาษาและไลบรารีฝั่งส่วนติดต่อผู้ใช้ (Front-End)

#### 2.2.1.1  TypeScript

TypeScript เป็นภาษาโปรแกรมที่พัฒนาต่อยอดจาก JavaScript โดยเพิ่มระบบชนิดข้อมูลแบบสแตติก (Static Typing) ทำให้สามารถตรวจจับข้อผิดพลาดของชนิดข้อมูลได้ตั้งแต่ขั้นตอนการคอมไพล์ ก่อนนำโค้ดไปทำงานจริง ระบบที่พัฒนานี้ใช้ TypeScript ทั้งฝั่งไคลเอนต์และเซิร์ฟเวอร์ พร้อมเปิดใช้ Strict Mode ที่กำหนดใน `tsconfig.json` เพื่อให้ผลลัพธ์ของการคอมไพล์มีคุณภาพสูงและลดบั๊กในขั้นการรันไทม์

#### 2.2.1.2  React 19

React เป็นไลบรารีสำหรับสร้างส่วนติดต่อผู้ใช้แบบคอมโพเนนต์ (Component-Based UI) พัฒนาโดย Meta (Facebook) React 19 เป็นรุ่นล่าสุดที่รองรับ Server Components และฟีเจอร์ใหม่อย่าง `useActionState` และ `useFormStatus` ที่ทำงานร่วมกับ Server Action ของ Next.js การออกแบบคอมโพเนนต์ใช้แนวคิดของ Unidirectional Data Flow ที่ทำให้สถานะของระบบสามารถคาดเดาและทดสอบได้ง่ายขึ้น

#### 2.2.1.3  Tailwind CSS และ shadcn/ui

Tailwind CSS เป็นเฟรมเวิร์กสำหรับการเขียนสไตล์แบบ Utility-First ที่ช่วยให้นักพัฒนากำหนดสไตล์ของอีลีเมนต์โดยใช้คลาสยูทิลิตี้ที่กำหนดไว้แล้ว ส่วน **shadcn/ui** คือคลังคอมโพเนนต์สำเร็จรูปบนพื้นฐานของ Radix UI ที่นำเสนอคอมโพเนนต์มาตรฐาน เช่น ปุ่ม, Dialog, Dropdown, Popover, Tooltip, Table โดยสามารถปรับแต่งสไตล์ผ่าน Tailwind ได้อย่างยืดหยุ่น ระบบนี้ใช้ shadcn/ui เพื่อให้ส่วนติดต่อผู้ใช้มีความเป็นอันหนึ่งอันเดียวกันและสอดคล้องกับหลัก WAI-ARIA สำหรับผู้ใช้ที่มีความต้องการพิเศษ

#### 2.2.1.4  Lucide React และ Tabler Icons

ระบบใช้ไลบรารีไอคอนแบบเวกเตอร์ ได้แก่ Lucide React และ Tabler Icons ซึ่งมีไอคอนคุณภาพสูงให้เลือกใช้กว่า 1,000 รายการ รองรับการปรับขนาดและสีโดยไม่เสียคุณภาพ ทำให้ส่วนติดต่อผู้ใช้ดูทันสมัยและสื่อความหมายชัดเจน

### 2.2.2  เฟรมเวิร์กและไลบรารีฝั่งเซิร์ฟเวอร์ (Back-End)

#### 2.2.2.1  Next.js 16 (App Router)

Next.js เป็นเฟรมเวิร์กบนพื้นฐานของ React ที่พัฒนาโดยบริษัท Vercel รองรับการเรนเดอร์แบบฝั่งเซิร์ฟเวอร์ การเรนเดอร์แบบสแตติก และการสร้าง API Route ภายในโครงการเดียวกัน รุ่นที่ใช้ในระบบนี้คือ Next.js 16 ที่ใช้รูปแบบ **App Router** ซึ่งจัดโครงสร้างไฟล์ตามเส้นทาง URL โดยตรง รองรับการแบ่งกลุ่มเส้นทาง (Route Groups), Layout แยกตามกลุ่ม, Streaming และ Suspense ทำให้พัฒนาแอปขนาดใหญ่ได้อย่างเป็นระบบ

#### 2.2.2.2  NextAuth.js v4

NextAuth.js เป็นไลบรารีสำหรับจัดการการยืนยันตัวตนในแอปพลิเคชันที่สร้างด้วย Next.js รองรับการตั้งค่าผู้ให้บริการยืนยันตัวตน (Provider) หลากหลาย รวมทั้งรูปแบบ Credentials Provider ที่ผู้พัฒนากำหนดตรรกะการยืนยันเอง ระบบนี้ตั้งค่าให้ใช้กลยุทธ์ JWT (Stateless Session) โดยเก็บค่า `role`, `studentId`, `uid` ใน JWT Payload เพื่อให้สามารถตรวจสอบสิทธิ์ของผู้ใช้ได้ทุกคำขอโดยไม่ต้องเข้าถึงฐานข้อมูล

#### 2.2.2.3  Prisma ORM

Prisma เป็น ORM สมัยใหม่สำหรับ Node.js และ TypeScript ที่ใช้ไฟล์ Schema เป็นแหล่งข้อมูลกลาง (Single Source of Truth) สำหรับโครงสร้างฐานข้อมูล Prisma สร้างไคลเอนต์ที่มีความปลอดภัยทางชนิดข้อมูลสูง (Type-Safe) อัตโนมัติ และรองรับการย้ายโครงสร้างฐานข้อมูล (Migration) ผ่านคำสั่ง `prisma migrate` ระบบนี้ใช้ Prisma 7 ร่วมกับ `@prisma/adapter-pg` สำหรับการเชื่อมต่อกับ PostgreSQL

#### 2.2.2.4  bcrypt และ jsonwebtoken

bcrypt เป็นอัลกอริทึมการแฮชรหัสผ่านที่ออกแบบให้ปรับระดับความซับซ้อน (Cost Factor) ได้ และทนทานต่อการโจมตีแบบ Brute Force ระบบนี้ใช้ bcrypt แฮชรหัสผ่านของผู้ใช้ทุกบทบาทก่อนเก็บลงฐานข้อมูล ส่วน jsonwebtoken เป็นไลบรารีที่ NextAuth ใช้ภายในเพื่อสร้างและตรวจสอบ JWT ตามมาตรฐาน RFC 7519

#### 2.2.2.5  Zod และ React Hook Form

Zod เป็นไลบรารีสำหรับนิยามและตรวจสอบโครงสร้างข้อมูล (Schema Validation) แบบ Type-Safe ระบบใช้ Zod ตรวจสอบข้อมูลที่รับเข้ามาทาง API Route และฟอร์ม เพื่อป้องกันการรับข้อมูลที่ผิดรูปแบบ ส่วน React Hook Form ใช้บริหารจัดการฟอร์มฝั่งไคลเอนต์ ทำให้การจัดการสถานะของฟอร์มเร็วและเขียนโค้ดได้สั้นกระชับ

### 2.2.3  ฐานข้อมูลและเครื่องมือเสริม

#### 2.2.3.1  PostgreSQL

PostgreSQL เป็นระบบจัดการฐานข้อมูลเชิงสัมพันธ์แบบโอเพนซอร์สที่มีคุณสมบัติครบถ้วน รองรับ ACID Transaction, JSON Type, Window Function และดัชนีหลายรูปแบบ ระบบนี้เลือกใช้ PostgreSQL เนื่องจากเสถียร รองรับข้อมูลขนาดใหญ่ และเข้ากันได้ดีกับ Prisma ORM

#### 2.2.3.2  Upstash Redis

Upstash Redis เป็นบริการ Redis บนคลาวด์แบบ Serverless ที่เปิดให้เรียกใช้งานผ่าน REST API ระบบนี้ใช้ Upstash Redis ร่วมกับ `@upstash/ratelimit` สำหรับจำกัดอัตราการยิงคำขอเข้าสู่ระบบ (Login Rate Limit) โดยกำหนดเพดานไว้ที่ 10 ครั้งต่อนาทีต่อหมายเลข IP เพื่อป้องกันการโจมตีแบบเดารหัสผ่าน (Credential Stuffing) แบบอัตโนมัติ

#### 2.2.3.3  @react-pdf/renderer

ไลบรารี `@react-pdf/renderer` ช่วยให้สามารถสร้างไฟล์ PDF จากคอมโพเนนต์ React ได้โดยตรง ระบบใช้ไลบรารีนี้สร้างไฟล์รายงานสรุปการยืม-คืนกุญแจที่ใช้ฟอนต์ไทย (Kanit และ Noto Sans Thai) เพื่อให้สามารถส่งออกรายงานเป็นเอกสารทางการได้

#### 2.2.3.4  jsQR

jsQR เป็นไลบรารี JavaScript ฝั่งไคลเอนต์ที่สามารถถอดรหัส QR Code จากภาพได้ ระบบใช้ jsQR สำหรับให้เจ้าหน้าที่และเครื่อง Kiosk สามารถอ่าน QR Token ของนักศึกษาได้ทั้งจากกล้องสดและจากภาพที่อัปโหลดเข้ามา

### 2.2.4  เครื่องมือพัฒนาและบริหารโค้ด

#### 2.2.4.1  Git และ GitHub

ระบบใช้ Git สำหรับการควบคุมเวอร์ชันของซอร์สโค้ด พร้อมใช้ GitHub เป็นแหล่งเก็บโค้ดและช่องทางความร่วมมือ การพัฒนาแบ่งสาขา (Branch) ตามฟีเจอร์ และรวมเข้ากับสาขาหลัก (main) ผ่าน Pull Request เมื่อผ่านการทบทวนแล้ว

#### 2.2.4.2  ESLint และ Prettier

ระบบใช้ ESLint ตรวจสอบรูปแบบและคุณภาพของโค้ด พร้อมกฎที่กำหนดสำหรับโครงการ Next.js (`eslint-config-next`) เพื่อให้โค้ดเป็นไปตามมาตรฐานเดียวกันทั้งโครงการ

#### 2.2.4.3  Node.js และ npm

Node.js เป็นรันไทม์ JavaScript ฝั่งเซิร์ฟเวอร์ที่พัฒนาโดย OpenJS Foundation รองรับการรันโค้ด TypeScript ผ่านเครื่องมือคอมไพล์ ระบบใช้ npm เป็นผู้จัดการแพ็กเกจสำหรับติดตั้งและบริหารไลบรารีที่ใช้งานในโครงการ

#### 2.2.4.4  Visual Studio Code

Visual Studio Code เป็นโปรแกรมแก้ไขข้อความสำหรับนักพัฒนาที่พัฒนาโดยบริษัท Microsoft รองรับการขยายความสามารถผ่านส่วนเสริม (Extension) เช่น ESLint, Prettier, Prisma, GitLens และ Tailwind CSS IntelliSense ผู้จัดทำใช้ Visual Studio Code เป็นเครื่องมือหลักในการเขียนและทดสอบโค้ด
