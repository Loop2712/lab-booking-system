5.1 สรุปผลการพัฒนาระบบ

โครงงานการพัฒนาระบบบริหารจัดการห้องปฏิบัติการคอมพิวเตอร์ อาคาร 75 ปี มหาวิทยาลัยราชภัฏวไลยอลงกรณ์ ในพระบรมราชูปถัมภ์ ผ่านระบบจองและยืม-คืนกุญแจออนไลน์ ประสบความสำเร็จในการแก้ไขปัญหาของระบบเดิมที่ใช้บัตรประจำตัวนักศึกษาแลกกุญแจและบันทึกด้วยมือ ซึ่งมีข้อจำกัดหลายประการ ได้แก่ ความเสี่ยงต่อการสูญหายของบัตร ความล่าช้าในกระบวนการ การสับสนของบัตรประจำตัวเมื่อมีผู้ใช้หลายคน และการขาดข้อมูลสถิติการใช้งาน

ระบบที่พัฒนาขึ้นด้วย Next.js 16 (แอปพลิเคชันเชิงเว็บแบบครบวงจร), React 19, TypeScript, Prisma ORM และ PostgreSQL รองรับผู้ใช้งาน 3 บทบาทหลัก ได้แก่ นักศึกษา อาจารย์ และผู้ดูแลระบบ โดยครอบคลุมทุกกระบวนการตั้งแต่การจองห้องล่วงหน้า การอนุมัติคำขอ การยืม-คืนกุญแจผ่านรหัส QR ไปจนถึงการสรุปรายงานผลการใช้งาน

ผลการดำเนินงานสอดคล้องกับวัตถุประสงค์ที่กำหนดไว้ครบทั้ง 3 ข้อ กล่าวคือ ประการแรก ระบบจองห้องปฏิบัติการผ่านเครือข่ายอินเทอร์เน็ตพัฒนาสำเร็จ รองรับการจอง 2 ประเภทพร้อมกระบวนการอนุมัติ ประการที่สอง ระบบยืม-คืนกุญแจที่ตรวจสอบสิทธิ์ด้วย QR Token และติดตามสถานะแบบทันทีพัฒนาสำเร็จ ทั้งในรูปแบบ Loan Desk และ Kiosk Self-Check และประการที่สาม ระบบรายงานสรุปผลการใช้งานที่กรองข้อมูลและส่งออกเป็น PDF พัฒนาสำเร็จ

ผลการทดสอบระบบด้วยกรณีทดสอบทั้งหมด 31 กรณี ผ่านร้อยละ 100 และผลการประเมินโดยผู้เชี่ยวชาญมีค่าเฉลี่ยรวม 4.52 จากคะแนนเต็ม 5.00 อยู่ในระดับ ดีมาก ส่วนผลการประเมินความพึงพอใจของผู้ใช้งานจำนวน 30 คนมีค่าเฉลี่ยรวม 4.37 จากคะแนนเต็ม 5.00 อยู่ในระดับ ดีมาก เช่นกัน แสดงให้เห็นว่าระบบมีคุณภาพและสามารถนำไปใช้งานจริงได้

นอกจากการบรรลุวัตถุประสงค์ทั้ง 3 ข้อแล้ว ระบบยังมีฟีเจอร์เพิ่มเติมที่เป็นประโยชน์ ได้แก่ ปฏิทินรายสัปดาห์แสดงตารางเรียนและการจองในภาพเดียว ระบบตรวจจับการไม่มาตามนัดอัตโนมัติด้วย Cron Job และระบบนำเข้าข้อมูลจำนวนมากผ่านไฟล์ XLSX หรือ CSV พร้อมตรวจสอบล่วงหน้าก่อนนำเข้าจริง ซึ่งช่วยลดภาระงานของผู้ดูแลระบบได้อย่างมีนัยสำคัญ

ระบบนี้เหมาะสมที่จะนำไปใช้งานจริงกับห้องปฏิบัติการคอมพิวเตอร์ของมหาวิทยาลัยราชภัฏวไลยอลงกรณ์ ในพระบรมราชูปถัมภ์ และสามารถเป็นต้นแบบสำหรับการพัฒนาระบบบริหารจัดการทรัพยากรของสถาบันการศึกษาอื่น ๆ ได้ต่อไปในอนาคต

5.2 ปัญหาและวิธีการแก้ไข

ในระหว่างการพัฒนาระบบพบปัญหาและอุปสรรคหลายประการ ซึ่งผู้พัฒนาได้ดำเนินการแก้ไขดังนี้

5.2.1 ปัญหาด้านการจัดการเขตเวลา (Timezone)

ระบบ Server เก็บข้อมูลวันและเวลาในรูปแบบ UTC ขณะที่ผู้ใช้งานและการตรวจสอบความขัดแย้งของเวลาต้องใช้เวลาในเขต Asia/Bangkok (UTC+7) ส่งผลให้เกิดความคลาดเคลื่อนในการแสดงวันที่และเวลาในบางกรณี

วิธีการแก้ไข ใช้ไลบรารี date-fns-tz ร่วมกับ date-fns เพื่อแปลงเวลาระหว่าง UTC และ Asia/Bangkok อย่างถูกต้อง กำหนดให้ฐานข้อมูลเก็บเวลาเป็น UTC เสมอ และแปลงเป็นเวลาท้องถิ่นเมื่อต้องการแสดงผลหรือประมวลผลทางธุรกิจ วิธีนี้ทำให้ปัญหาหมดไปได้อย่างสมบูรณ์

5.2.2 ปัญหาความซับซ้อนของกระบวนการจอง

ระบบมีกระบวนการที่ซับซ้อน เนื่องจากการจองมี 2 ประเภทและมีสถานะถึง 7 สถานะ ทำให้การเขียนตรรกะการตรวจสอบสิทธิ์และการเปลี่ยนสถานะมีความซับซ้อนสูง และเกิดข้อผิดพลาดในช่วงแรกของการพัฒนา

วิธีการแก้ไข ออกแบบ State Machine สำหรับการเปลี่ยนสถานะอย่างชัดเจน และเขียนฟังก์ชันตรวจสอบแยกต่างหากสำหรับแต่ละประเภทของการจอง พร้อมทั้งทดสอบกรณีพิเศษต่าง ๆ อย่างครอบคลุม ทำให้ระบบทำงานได้ถูกต้องสมบูรณ์

5.2.3 ปัญหาความปลอดภัยของรหัส QR Token

รหัส QR Token ต้องมีความปลอดภัยสูงเพื่อป้องกันการนำไปใช้ซ้ำหรือการปลอมแปลง แต่ในขณะเดียวกันต้องใช้งานได้สะดวกและรวดเร็ว

วิธีการแก้ไข กำหนดอายุการใช้งานของ Token เพียง 2 นาที ใช้มาตรฐาน JWT (JSON Web Token) ที่ลงนามด้วยรหัสลับ และจัดทำระบบรีเฟรช Token อัตโนมัติฝั่งผู้ใช้งาน ทำให้ผู้ใช้ไม่ต้องรีเฟรชเองและมีความปลอดภัยในระดับที่เหมาะสม

5.2.4 ปัญหาการตรวจสอบความขัดแย้งของการจอง

การตรวจสอบว่าช่วงเวลาที่ต้องการจองว่างอยู่หรือไม่ต้องพิจารณาทั้งการจองประเภท IN_CLASS จากตาราง Section และการจองประเภท AD_HOC จากตาราง Reservation พร้อมกัน ทำให้คำสั่งการค้นหาข้อมูล (Query) มีความซับซ้อนสูง

วิธีการแก้ไข สร้าง API Endpoint สำหรับตรวจสอบความพร้อมใช้งานโดยเฉพาะ โดยค้นหาทั้ง Section และ Reservation ในคำสั่งเดียว พร้อมสร้าง Index ที่เหมาะสมบนฐานข้อมูล PostgreSQL ทำให้การตรวจสอบมีความเร็วและถูกต้อง

5.2.5 ปัญหาการออกแบบระบบ Kiosk

การออกแบบ Kiosk ให้ใช้งานได้โดยไม่ต้องล็อกอิน แต่ยังต้องมีความปลอดภัยและป้องกันการใช้งานโดยอุปกรณ์ที่ไม่ได้รับอนุญาต เป็นความท้าทายด้านสถาปัตยกรรมระบบ

วิธีการแก้ไข ออกแบบระบบการจับคู่อุปกรณ์ (Device Pairing) โดยให้ผู้ดูแลระบบจับคู่อุปกรณ์ Kiosk กับระบบก่อนใช้งาน ผ่านรหัส KioskToken ที่เก็บในฐานข้อมูลเพื่อตรวจสอบสิทธิ์อุปกรณ์แต่ละเครื่อง ทำให้ระบบทั้งสะดวกและปลอดภัย

5.3 ข้อเสนอแนะ

จากการพัฒนาและทดสอบระบบ ผู้พัฒนาขอเสนอแนะแนวทางสำหรับการปรับปรุงและพัฒนาต่อยอดระบบในอนาคตดังนี้

5.3.1 ข้อเสนอแนะด้านฟังก์ชันการทำงาน
  1. ควรเพิ่มระบบแจ้งเตือนผ่าน Line Notify หรืออีเมล เมื่อมีการอนุมัติหรือปฏิเสธการจอง การยืม-คืนกุญแจ หรือการจองใกล้ถึงกำหนด เพื่อให้ผู้ใช้ไม่พลาดกิจกรรมสำคัญ
  2. ควรพัฒนาแอปพลิเคชันบนโทรศัพท์มือถือ (iOS หรือ Android) เพื่อให้ผู้ใช้งานสามารถจองห้องและแสดงรหัส QR ได้สะดวกยิ่งขึ้นโดยไม่ต้องเปิดเบราว์เซอร์
  3. ควรเพิ่มฟีเจอร์แนะนำห้องที่ว่างอยู่โดยอัตโนมัติตามจำนวนผู้เข้าร่วม เพื่อช่วยให้การจองทำได้เร็วขึ้น
  4. ควรพัฒนาให้รองรับการจองห้องหลายห้องในคำขอเดียว สำหรับกิจกรรมขนาดใหญ่ที่ต้องใช้หลายห้องพร้อมกัน
5.3.2 ข้อเสนอแนะด้านความปลอดภัยและประสิทธิภาพ
  1. ควรเพิ่มระบบยืนยันตัวตนสองชั้น (Two-Factor Authentication หรือ 2FA) โดยเฉพาะสำหรับบัญชีผู้ดูแลระบบ เพื่อป้องกันการเข้าถึงโดยไม่ได้รับอนุญาต
  2. ควรเพิ่มระบบบันทึกการดำเนินการ (Audit Log) สำหรับทุกการกระทำสำคัญ เช่น การเข้าสู่ระบบ การแก้ไขข้อมูล และการยืม-คืนกุญแจ เพื่อให้สามารถตรวจสอบย้อนหลังได้
  3. ควรเพิ่มระบบ Caching สำหรับข้อมูลที่ถูกอ่านบ่อย เช่น สถานะห้องวันนี้และข้อมูลตารางเรียน เพื่อเพิ่มประสิทธิภาพการตอบสนองของระบบ
  4. ควรจัดทำกระบวนการสำรองฐานข้อมูลอัตโนมัติรายวันและทดสอบการนำข้อมูลสำรองกลับมาใช้งาน เพื่อรับมือกับสถานการณ์ฉุกเฉิน
5.3.3 ข้อเสนอแนะด้านการขยายขอบเขต
  1. ปัจจุบันระบบถูกพัฒนาสำหรับอาคาร 75 ปี เพียงแห่งเดียว ควรขยายระบบให้รองรับหลายอาคารเพื่อเพิ่มประโยชน์ให้กับมหาวิทยาลัยในวงกว้าง
  2. ควรเชื่อมต่อ API กับระบบทะเบียนกลางของมหาวิทยาลัยเพื่อนำเข้าข้อมูลนักศึกษา อาจารย์ และตารางเรียนโดยอัตโนมัติ ลดความซ้ำซ้อนในการดูแลรักษาข้อมูล
  3. ควรเพิ่มกราฟและสถิติเชิงลึกสำหรับผู้บริหาร เช่น ห้องที่ใช้งานบ่อยที่สุด ช่วงเวลาที่มีการจองหนาแน่น และแนวโน้มการใช้งาน เพื่อสนับสนุนการตัดสินใจด้านการบริหารจัดการ
  4. ควรขยายระบบให้รองรับการจองอุปกรณ์พิเศษภายในห้องปฏิบัติการ เช่น โปรเจกเตอร์ กล้อง หรืออุปกรณ์เครือข่าย เพื่อให้การบริหารจัดการทรัพยากรมีความครอบคลุมมากยิ่งขึ้น

สรุปโดยรวมแล้ว ระบบบริหารจัดการห้องปฏิบัติการคอมพิวเตอร์ที่พัฒนาขึ้นมีความสามารถและประสิทธิภาพเพียงพอที่จะนำไปใช้งานจริง และสามารถช่วยยกระดับการบริหารจัดการห้องปฏิบัติการให้มีความทันสมัย ลดภาระงานของเจ้าหน้าที่ และเพิ่มความสะดวกสบายให้กับผู้ใช้งานทุกกลุ่ม ทั้งนักศึกษา อาจารย์ และผู้บริหาร ซึ่งสอดคล้องกับทิศทางการพัฒนาด้านเทคโนโลยีสารสนเทศของมหาวิทยาลัยในปัจจุบัน
