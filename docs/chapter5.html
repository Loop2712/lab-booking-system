บทที่ 5
สรุปผลการดำเนินงานและข้อเสนอแนะ

บทนี้นำเสนอสรุปผลการดำเนินโครงงานพัฒนาระบบบริหารจัดการห้องปฏิบัติการคอมพิวเตอร์ อาคาร 75 ปี มหาวิทยาลัยราชภัฏวไลยอลงกรณ์ ในพระบรมราชูปถัมภ์ ผ่านระบบจองและยืม-คืนกุญแจออนไลน์ โดยสรุปผลที่ได้รับตามวัตถุประสงค์ ปัญหาและอุปสรรคที่พบระหว่างการพัฒนา และข้อเสนอแนะสำหรับการพัฒนาต่อยอดในอนาคต

5.1 สรุปผลการดำเนินงาน

โครงงานนี้ได้พัฒนาระบบบริหารจัดการห้องปฏิบัติการคอมพิวเตอร์แบบ Web Application ด้วย Next.js 16, React 19, TypeScript, Prisma ORM และ PostgreSQL รองรับผู้ใช้งาน 3 บทบาทหลัก ได้แก่ นักศึกษา อาจารย์ และผู้ดูแลระบบ โดยผลการดำเนินงานสอดคล้องกับวัตถุประสงค์ที่กำหนดไว้ทั้ง 3 ข้อ ดังนี้

ตารางที่ 5.1 ผลการดำเนินงานตามวัตถุประสงค์

ที่ วัตถุประสงค์ ผลที่ได้รับ สถานะ
1 พัฒนาระบบจองห้องปฏิบัติการคอมพิวเตอร์ผ่านเครือข่ายอินเทอร์เน็ต ระบบรองรับการจอง 2 ประเภท (IN_CLASS และ AD_HOC) ตรวจสอบ Conflict แบบ Real-time รองรับผู้เข้าร่วมสูงสุด 4 คน และมี Workflow อนุมัติการจองผ่านอาจารย์ ✓ บรรลุ
2 พัฒนาระบบยืม-คืนกุญแจห้องปฏิบัติการที่สามารถตรวจสอบสิทธิ์และติดตามสถานะได้แบบเรียลไทม์ ระบบยืนยันตัวตนผ่าน QR Token (JWT) ที่หมดอายุทุก 2 นาที รองรับทั้งแบบ Loan Desk (เจ้าหน้าที่) และ Kiosk Self-Check (ด้วยตนเอง) ติดตามสถานะกุญแจแบบ Real-time ✓ บรรลุ
3 พัฒนาระบบรายงานสรุปผลการใช้งานห้องปฏิบัติการและสถิติการยืม-คืนกุญแจ ระบบรายงานกรองได้ตามช่วงเวลา ประเภท สถานะ ห้อง และผู้จอง แสดง Summary Cards และรองรับ Export เป็น PDF ผ่าน @react-pdf/renderer ✓ บรรลุ

นอกจากการบรรลุวัตถุประสงค์ทั้ง 3 ข้อแล้ว ระบบยังมีฟีเจอร์เพิ่มเติมที่พัฒนาขึ้นตามความต้องการของผู้ใช้งาน ได้แก่ ระบบปฏิทินรายสัปดาห์ ระบบการจัดการตารางเรียน ระบบ No-show อัตโนมัติ และระบบนำเข้าข้อมูลจำนวนมากผ่านไฟล์ CSV/XLSX

สรุปผลการทดสอบและประเมิน:
• กรณีทดสอบผ่านทั้งหมด 31 / 31 กรณี (ร้อยละ 100)
• ผลประเมินประสิทธิภาพโดยผู้เชี่ยวชาญ ค่าเฉลี่ยรวม 4.52 / 5.00 ระดับ ดีมาก
• ผลประเมินความพึงพอใจผู้ใช้งาน ค่าเฉลี่ยรวม 4.37 / 5.00 ระดับ ดีมาก
5.2 ผลที่ได้รับตามขอบเขตของโครงงาน

5.2.1 ผลที่ผู้ดูแลระบบได้รับ

ผู้ดูแลระบบสามารถจัดการข้อมูลทั้งหมดของระบบ ไม่ว่าจะเป็นข้อมูลผู้ใช้งาน ห้องปฏิบัติการ กุญแจ รายวิชา กลุ่มเรียน และภาคการศึกษา ผ่านหน้าจอที่ใช้งานง่าย รองรับการนำเข้าข้อมูลจำนวนมากผ่านไฟล์ CSV/XLSX พร้อม Dry-run Preview ก่อนนำเข้าจริงเพื่อลดข้อผิดพลาด นอกจากนี้ยังสามารถดูรายงานสรุปการใช้งานห้องและสถิติการยืม-คืนกุญแจ เพื่อใช้วางแผนบริหารจัดการต่อไป

5.2.2 ผลที่อาจารย์ได้รับ

อาจารย์สามารถตรวจสอบตารางการใช้งานห้องปฏิบัติการได้แบบ Real-time จองห้องล่วงหน้าสำหรับกิจกรรมนอกตาราง ดูและอนุมัติหรือปฏิเสธคำขอจองของนักศึกษา รวมถึงยืม-คืนกุญแจโดยใช้ QR Token ผ่านทั้งระบบ Loan Desk และ Kiosk Self-Check ปฏิทินรายสัปดาห์ช่วยให้อาจารย์มองเห็นตารางสอนและการจองในภาพรวมได้อย่างสะดวก

5.2.3 ผลที่นักศึกษาได้รับ

นักศึกษาสามารถตรวจสอบสถานะห้องปฏิบัติการ จองห้องล่วงหน้าสำหรับกิจกรรมกลุ่ม และเพิ่มผู้เข้าร่วมได้สูงสุด 4 คน ระบบ QR Token ช่วยให้นักศึกษาไม่ต้องนำบัตรประจำตัวมาแลกกุญแจอีกต่อไป ลดความเสี่ยงการสูญหายหรือสับสนของบัตร ปฏิทินรายสัปดาห์แสดงตารางเรียนและการจองรวมในที่เดียว ช่วยให้วางแผนการใช้ห้องได้อย่างมีประสิทธิภาพ

5.3 ปัญหาและอุปสรรคที่พบในการดำเนินงาน

ในระหว่างการพัฒนาระบบ พบปัญหาและอุปสรรคหลายประการ ซึ่งผู้พัฒนาได้หาแนวทางแก้ไขดังนี้

5.3.1 ปัญหาด้านการจัดการ Timezone

ปัญหาที่พบคือระบบ Server เก็บเวลาในรูปแบบ UTC ในขณะที่การแสดงผลและการตรวจสอบ Conflict ต้องใช้เวลาในเขต Asia/Bangkok (UTC+7) ทำให้เกิดความคลาดเคลื่อนในการแสดงวันที่และเวลา

แนวทางแก้ไข: ใช้ไลบรารี date-fns-tz ร่วมกับ date-fns เพื่อแปลงเวลาระหว่าง UTC และ Asia/Bangkok อย่างถูกต้อง กำหนดให้ฐานข้อมูลเก็บเวลาเป็น UTC เสมอ และแปลงเป็น Bangkok Time เมื่อแสดงผลหรือประมวลผลทางธุรกิจ

5.3.2 ปัญหาด้านความซับซ้อนของ Workflow การจอง

ระบบมี Workflow ที่ซับซ้อน เนื่องจากการจองมี 2 ประเภท (IN_CLASS และ AD_HOC) และมีสถานะถึง 7 สถานะ (PENDING, APPROVED, REJECTED, CANCELLED, NO_SHOW, CHECKED_IN, COMPLETED) ทำให้การเขียนตรรกะการตรวจสอบสิทธิ์และการเปลี่ยนสถานะมีความซับซ้อนสูง

แนวทางแก้ไข: ออกแบบ State Machine สำหรับการเปลี่ยนสถานะอย่างชัดเจน และเขียน Validation Functions แยกต่างหากสำหรับแต่ละประเภทของการจอง พร้อมทั้งเขียน Unit Test ครอบคลุม Edge Cases ต่าง ๆ

5.3.3 ปัญหาการรักษาความปลอดภัยของ QR Token

เนื่องจาก QR Token ถูกส่งผ่านเครือข่ายและอาจถูกดักจับหรือนำไปใช้ซ้ำได้ จึงต้องมีการออกแบบระบบรักษาความปลอดภัยที่รัดกุม

แนวทางแก้ไข: กำหนดอายุการใช้งานของ Token เพียง 2 นาที ใช้ JWT ที่ลงนามด้วย Secret Key (QR_TOKEN_SECRET) และตรวจสอบ Token ทุกครั้งที่ใช้งาน พร้อมระบบรีเฟรช Token อัตโนมัติฝั่ง Client

5.3.4 ปัญหาการตรวจสอบ Conflict ของการจอง

การตรวจสอบว่าช่วงเวลาที่ต้องการจองว่างอยู่หรือไม่ต้องพิจารณาทั้งการจองประเภท IN_CLASS จากตาราง Section และการจองประเภท AD_HOC จากตาราง Reservation พร้อมกัน ทำให้ Query มีความซับซ้อนสูง

แนวทางแก้ไข: สร้าง API Endpoint สำหรับตรวจสอบ Availability โดยเฉพาะ โดย Query ทั้ง Section และ Reservation ในคำสั่งเดียว พร้อม Index ที่เหมาะสมบนฐานข้อมูล PostgreSQL เพื่อเพิ่มความเร็วในการตรวจสอบ

5.3.5 ปัญหาการออกแบบระบบ Kiosk

การออกแบบ Kiosk ให้ใช้งานได้โดยไม่ต้องล็อกอิน แต่ยังต้องมีความปลอดภัยและป้องกันการใช้งานโดยไม่ได้รับอนุญาต เป็นความท้าทายด้านการออกแบบ

แนวทางแก้ไข: ออกแบบระบบ Pairing Token ให้แอดมินจับคู่อุปกรณ์ Kiosk กับระบบก่อนใช้งาน โดยใช้ KioskToken ที่เก็บในฐานข้อมูลเพื่อตรวจสอบสิทธิ์อุปกรณ์แต่ละเครื่อง
5.4 ข้อเสนอแนะสำหรับการพัฒนาต่อยอด

จากการพัฒนาและทดสอบระบบ ผู้พัฒนาขอเสนอแนะแนวทางสำหรับการพัฒนาระบบต่อยอดในอนาคตดังนี้

5.4.1 ข้อเสนอแนะด้านฟังก์ชันการทำงาน

  • ระบบแจ้งเตือนผ่าน Line Notify หรือ Email: เพิ่มการแจ้งเตือนอัตโนมัติเมื่อมีการอนุมัติ/ปฏิเสธการจอง การยืม-คืนกุญแจ หรือการจองใกล้ถึงกำหนด เพื่อให้ผู้ใช้ไม่พลาดกิจกรรมสำคัญ
  • ระบบ Mobile Application: พัฒนาแอปพลิเคชันบนมือถือ (iOS/Android) เพื่อให้ผู้ใช้งานสามารถจองห้องและแสดง QR Token ได้สะดวกยิ่งขึ้นโดยไม่ต้องเปิด Browser
  • ระบบการจัดสรรห้องอัตโนมัติ: เพิ่มฟีเจอร์แนะนำห้องที่ว่างอยู่โดยอัตโนมัติตามจำนวนผู้เข้าร่วม ช่วยให้การจองทำได้เร็วขึ้น
  • รองรับการยืมกุญแจหลายห้องพร้อมกัน: ปัจจุบันระบบรองรับการจองได้ทีละห้อง การพัฒนาให้รองรับการจองหลายห้องในคำขอเดียวจะเป็นประโยชน์สำหรับกิจกรรมขนาดใหญ่
  • ระบบประเมินการใช้งาน (Feedback): เพิ่มฟอร์มให้ผู้ใช้งานประเมินความพึงพอใจหลังใช้บริการ เพื่อนำข้อมูลไปปรับปรุงระบบอย่างต่อเนื่อง

5.4.2 ข้อเสนอแนะด้านความปลอดภัยและประสิทธิภาพ

  • เพิ่มระบบ Two-Factor Authentication (2FA): เพิ่มขั้นตอนการยืนยันตัวตนสองชั้น โดยเฉพาะสำหรับบัญชีผู้ดูแลระบบ เพื่อป้องกันการเข้าถึงโดยไม่ได้รับอนุญาต
  • ระบบ Audit Log: เพิ่มการบันทึก Log ทุกการดำเนินการสำคัญ เช่น การเข้าสู่ระบบ การแก้ไขข้อมูล และการยืม-คืนกุญแจ เพื่อให้สามารถตรวจสอบย้อนหลังได้
  • Caching ด้วย Redis: เพิ่มระบบ Cache สำหรับข้อมูลที่ถูกอ่านบ่อย เช่น สถานะห้องวันนี้ และข้อมูลตารางเรียน เพื่อเพิ่มประสิทธิภาพการตอบสนองของระบบ
  • ระบบสำรองข้อมูลอัตโนมัติ: กำหนดกระบวนการสำรองฐานข้อมูล PostgreSQL อัตโนมัติรายวัน และทดสอบการ Restore เพื่อรับมือกับสถานการณ์ฉุกเฉิน

5.4.3 ข้อเสนอแนะด้านการขยายขอบเขต

  • รองรับอาคารหลายแห่ง: ปัจจุบันระบบถูกพัฒนาสำหรับอาคาร 75 ปี เพียงแห่งเดียว การขยายระบบให้รองรับหลายอาคารจะเพิ่มประโยชน์ให้กับมหาวิทยาลัยได้มาก
  • เชื่อมต่อกับระบบทะเบียนมหาวิทยาลัย: เชื่อมต่อ API กับระบบทะเบียนกลางของมหาวิทยาลัยเพื่อนำเข้าข้อมูลนักศึกษา อาจารย์ และตารางเรียนโดยอัตโนมัติ ลดความซ้ำซ้อนในการบำรุงรักษาข้อมูล
  • รองรับการจองอุปกรณ์คอมพิวเตอร์เพิ่มเติม: ขยายระบบให้รองรับการจองอุปกรณ์พิเศษภายในห้องปฏิบัติการ เช่น โปรเจกเตอร์ กล้อง หรืออุปกรณ์เครือข่าย
  • Dashboard Analytics: เพิ่มกราฟและสถิติเชิงลึกสำหรับผู้บริหาร เช่น ห้องที่ใช้งานบ่อยที่สุด ช่วงเวลาที่มีการจองหนาแน่น และแนวโน้มการใช้งาน เพื่อสนับสนุนการตัดสินใจ
5.5 บทสรุป

โครงงานการพัฒนาระบบบริหารจัดการห้องปฏิบัติการคอมพิวเตอร์ อาคาร 75 ปี มหาวิทยาลัยราชภัฏวไลยอลงกรณ์ ในพระบรมราชูปถัมภ์ ผ่านระบบจองและยืม-คืนกุญแจออนไลน์ ประสบความสำเร็จในการแก้ไขปัญหาของระบบเดิมที่ใช้บัตรประจำตัวนักศึกษาแลกกุญแจและบันทึกด้วยมือ ซึ่งมีข้อจำกัดหลายประการ ได้แก่ ความเสี่ยงต่อการสูญหายของบัตร ความล่าช้าในกระบวนการ และการขาดข้อมูลสถิติการใช้งาน

ระบบใหม่ที่พัฒนาขึ้นได้รับการออกแบบให้มีความปลอดภัย สะดวกใช้งาน และครอบคลุมทุกกระบวนการทำงาน ตั้งแต่การจองห้อง การอนุมัติ การยืม-คืนกุญแจ ไปจนถึงการสรุปรายงาน ด้วยเทคโนโลยีสมัยใหม่อย่าง Next.js, TypeScript, Prisma ORM และ PostgreSQL ทำให้ระบบมีความเสถียร ปลอดภัย และสามารถบำรุงรักษาได้ในระยะยาว

ผลการทดสอบระบบพบว่าทุกกรณีทดสอบผ่านร้อยละ 100 และผลการประเมินโดยผู้เชี่ยวชาญและผู้ใช้งานอยู่ในระดับดีมาก สะท้อนให้เห็นว่าระบบมีคุณภาพตรงตามความต้องการของผู้ใช้งานและสามารถนำไปใช้งานจริงได้ทันที อีกทั้งยังเป็นต้นแบบสำหรับการพัฒนาระบบบริหารจัดการทรัพยากรของสถาบันการศึกษาอื่น ๆ ต่อไปในอนาคต

ดาวรถา วีระพันธ. (2562). ระบบสารสนเทศจัดการข้อมูลสุขภาพของบุคลากรและนักศึกษาด้วยเทคโนโลยีบาร์โค้ด. มหาวิทยาลัยราชภัฏวไลยอลงกรณ์ ในพระบรมราชูปถัมภ์.

นันทนา รัตนชัย และคณะ. (2558). ระบบยืม-คืนปริญญานิพนธ์สำหรับสาขาคอมพิวเตอร์. วารสารวิทยาศาสตร์และเทคโนโลยี.

พงษ์พิชญ์ อุดมศิริรัตน์ และนุชนาฎ สัตยากวี. (2560). ระบบยืมคืนอุปกรณ์ห้องปฏิบัติการวิจัย ภาควิชาวิศวกรรมคอมพิวเตอร์ คณะวิศวกรรมศาสตร์ กำแพงแสน. มหาวิทยาลัยเกษตรศาสตร์.

พิทย์พิมล ชูรอด, เนาวลักษณ์ แสงสนิท และสุพิริยา ผลนาค. (2557). ระบบยืมหนังสือด้วยเครื่องสแกนลายนิ้วมือของสำนักหอสมุด มหาวิทยาลัยทักษิณ วิทยาเขตพัทลุง. มหาวิทยาลัยทักษิณ.

อดิศักดิ์ พวงสมบัติ. (2556). ระบบยืม-คืนครุภัณฑ์ด้วยบาร์โค้ดสองมิติ. วิทยานิพนธ์ระดับปริญญาตรี.
